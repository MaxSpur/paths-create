# NetMob pilot

NetMob offers a session-only, explicit-pair pilot alongside Manual, plus supervision of durable local jobs through the optional [loopback controller](NETMOB_RUNS.md). One generated trip represents one EMG row. Survey weights remain metadata, never replication counts. Raw Parquet files stay in ignored `local/` or another user-selected directory; production builds contain only public boundary supplements and derived transit assets.

## Ownership and contracts

- `netmobData.ts` / `netmob.worker.ts`: schema recognition, scalar normalization, SHA-256 dataset identity, polygon indexing, eligibility, filters, conditional facets and 50-row queries; explicit selections use a separate source-row offset (up to 1,000 rows). One worker owns each imported dataset; geometry is decoded once per area. Only pages, selected records and referenced areas cross into the UI. Close dataset terminates its worker.
- `netmobGeometry.ts`: reproducible Polygon/MultiPolygon sampling, holes, component-area weighting and short within-area proposals. Seed = dataset SHA-256 + source key + user seed + realization. Trials are stable across individual/batch order. Sampling is geographical; no buildings, workplaces, households or daily-journey continuity are inferred.
- `netmobRouting.ts`: explicit pairs, ordered street/transit legs, fitting and bounded batch reports. `generator.ts` retains the manual random-pair API and mode precedence. NetMob never enters persisted state normalization or manual pairing caches.
- `netmobTiming.ts` / `build-transit-timing.py`: recent scheduled-service estimates, with source hash/dates, sample counts, day/time bands and explicit fallback provenance.
- `netmobGenerate.worker.ts`: route generation and transit assets off the UI thread; abortable ORS requests and cooperative trial yields. Completed records return immediately and survive cancellation/service failure. Retry snapshots retain the original records, areas, seed and fitting settings, even after filters/settings change or a dataset closes. Routing provider/access limits are read at retry time so users can resolve service failures.
- `ui/netmob.ts`: Explore → Prepare pairs → Generate → Review/export. Separate session state shares MapView; switching modes retains Manual places, selections, results and settings. Delete/Backspace in NetMob cannot delete hidden manual points. Inspect frames the complete OD polygons without requiring preparation. Review map visibility is independent of pagination and details selection. Checked individual trips and whole batches can be combined without a 50/100-route cap; preparation previews still show one 50-row page or at most 64 endpoint proposals for one row; fitted endpoints replace prepared proposals when reviewing results.

Explore dropdowns contain all normalized modes, recorded sequences and purposes available under the other applied filters. Each facet omits its own filter; date and duration facets omit both ends of their respective range. Dates have a month/day availability heatmap and native input bounds; durations use the available positive range, including flagged anomalies. Dropdown changes apply automatically; text/range changes use Apply filters. Empty-result submissions retain the previous applied selection. Origin/destination remain free-text searches. Source values are never rewritten by display normalization.

Filtered source windows are distinct from 50-pair map pages. Prepare filtered batch selects the displayed range; Prepare next source batch advances by the configured source-row count, including failures/exclusions. Previous source batch returns to the earlier range. Changing filters or batch settings resets the range. Generate prepared is disabled after a run; retry uses the original job snapshot. All retained batches are checked for successful dataset/row/seed/realization identities before ordinary generation or retry, preventing repeated successes even across overlapping filters. Delete releases that batch's identity protection along with its results. Change realization to intentionally generate another sample. Failed/excluded/unprocessed records remain in reports and can be explicitly retried.

Preparation can show all geographical endpoint proposals for one selected row. These are candidates, not routed geometries: inferred-mode and scooter variants share the fixed trial budget across fewer pairs. During fitting the generation worker emits the actual candidate endpoints, trial index and mode sequence, without duplicating polygon payloads; the UI optionally shows the active pair at no more than four redraws per second. Processed/total and completed-route counts appear above the progress bar only; the current trip/mode/trial line is single-line with ellipsis. Counts remain visible with previews off. Failed/excluded records count as processed. The worker yields and routing trial order do not depend on drawing. The closest complete route is retained, regardless of whether it meets tolerance.

`ui/netmobMap.ts` owns the lazy canvas overlay. Route layers and deduplicated area outlines are retained across highlight changes; visibility changes add/remove only affected route geometry. Endpoint clicks select their owning generated trip; area clicks highlight all currently visible trips whose origin or destination has that exact area code. The open batch supplies the overview. List/endpoint selection opens details and focuses a route without changing any checkbox. Unchecked routes, points and outlines fade to the Unfocused visibility setting (default 0%); independent route and batch checkboxes pin items at normal visibility, including across batches. All pins start off. Background clicks clear focus, while dragging retains it. Map appearance controls independently scale points, paths and outlines, and adjust only the tile pane saturation/brightness; Manual mode restores the normal basemap. The bottom-right map panel and its Colors section collapse independently. `ui/netmobAppearance.ts` owns stable slider/color-picker DOM; double-click brightness restores 100%. Slider input patches map styles and readouts without rebuilding the panel. Generated transit legs retain `lineColor` from the pinned IDFM GTFS network. Default colors use that published line color, with explicit method fallbacks when unavailable. User method overrides take precedence over published colors; line-specific overrides take precedence over methods. Origin/destination outlines and points plus OD connectors are editable. Default colors clears only the palette overrides, preserving opacity and basemap settings. Appearance is session-only and does not rewrite source or export metadata. Export scope does not follow map visibility. Showing more than 1,000 routes displays a performance advisory, not a silent truncation. Practical capacity depends on total vertices, boundary complexity and the browser; full-dataset rendering is not validated.

Batch labels retain preparation-time filters and source windows; compact route labels use the within-batch number and original source mode sequence. Full source keys remain in details and exports. Route details show the original mode sequence, principal mode, generated sequence, fidelity/assumptions and complete original scalar metadata. GeoParquet `trip_json.netmob.raw` and GPX `odc:netmob.raw` preserve every normalized non-geometric source field, including nulls, original mode spelling, times, purpose and survey weights. Import excludes source `geom_o` and `centroid_o` payloads; exports carry generated route geometry, sampled endpoints and boundary provenance instead. Dates are normalized to ISO date strings. Exact original source-file bytes are not embedded.

A 512-entry per-run cache stores successful ORS metrics/geometry keyed by provider/elevation identity, profile and exact ordered coordinates. It stores no itinerary or timetable totals; those are recomputed against the injected immutable network/timing versions, sequence restrictions and departure bands. Rebuild local ORS graphs between runs, not during a fit. Speeds and statistics remain fixed within a run.

## Input and eligibility

EMG is recognized by `code_insee_o`/`code_insee_d`; the cube by `origine`/`destination`/`volume`. Other schemas fail visibly. Missing modes remain unknown; missing/nonpositive duration is unassessed. Source values and mode spelling/case are preserved; ordered modes are normalized separately. Duplicate source keys exclude subsequent rows. Arrival `heure_d` is retained raw and never used for timing. Departure uses `date_o` + `heure_o` as Europe/Paris wall time; invalid values and date/duration inconsistencies are flagged, not repaired. Durations over 24 hours are flagged as anomalous.

The supplied EMG has 80,694 rows, 1,036 source polygons and 34,670 within-area records. The supplement adds Paris `75101`–`75120`, Guillerval `91294` and Mondreville `77297`, keeping `75056` distinct. This yields 1,058 areas and 75,784 geographically eligible rows. Exclusion counts overlap: 4,910 outside IDF/missing code, 4,273 missing geometry, 27 containing flights (including secondary modes). Eligibility does not promise a route. The 176,084-row cube has neither a geographic crosswalk nor transport modes, so it remains exploration-only; its volume sum is separate from EMG survey weights.

## Mode and fit model

| Source token | Pilot routing |
| --- | --- |
| MAP | ORS pedestrian geometry/duration |
| VPC, VPP, TAXI/VTC, VUL, 2RM | ORS driving, original vehicle category retained; passenger/taxi/van/motorbike proxy disclosed |
| VELO / VAE | ORS cycling; normal ORS duration / fixed 20 km/h for electric bicycle |
| TROTTINETTE | Compare pedestrian and cycling geometries at fixed 12 km/h; chosen proxy disclosed |
| METRO, RER/TRAIN, TRAM, BUS | Exact ordered boarding-mode constraints, including repeated boardings; necessary walking connections |
| TGV/INTERCITES/TER | Only retained regional-rail services marked by the source TER agency; unavailable TGV/intercity coverage fails visibly |
| TAD | Road approximation with unverified booking/service |
| Missing / AUTRE / other | Compare driving, transit with walking and walking within the total trial budget; label inference |

Mixed sequences preserve all recorded stages. A single adjacent street leg connects through boarding/alighting candidates. Multiple separated transit runs or consecutive street changes use deterministic OD-corridor intermediate checkpoints and are explicitly approximate. Vehicle availability/parking is assumed. Snaps over 500 m fail, effective first/last endpoints must remain inside their assigned polygons, and short gaps between legs become timed, explicitly approximate walking connectors. Longer unresolved gaps fail.

Default 12 total route trials (1–64), including inferred-mode/scooter alternatives. Cheap geographical duration estimates prioritize proposals. The UI defaults to simulated movement duration: each complete route receives a duration-only kinematic evaluation before ranking by absolute error against the observed duration. ORS/timetable scoring remains selectable; callers omitting `durationModel` retain legacy routing scoring. Dense samples/noise are not generated during fitting. The chosen preset is frozen in the job/retry snapshot and retained with model version, movement duration and the independent routing duration. Original leg durations/offsets remain routing estimates. Acceptable means error ≤ max(180 seconds, 20% of observed duration), both configurable. The closest valid poor fit is retained; missing duration is “unassessed.” Without a usable duration, unknown modes retain the first geographically valid proxy and disclose that selection rule. Timing is never stretched to force a match.

Transit estimates use directed retained services from the pinned September 2026 feed. Preprocessing uses one representative active date per weekday/Saturday/Sunday category, calendar exceptions, after-midnight calendar rollover, median inter-stop running seconds and median half-headways from bounded 127-value reservoirs. Each statistic retains its full sample count. Bands are 00–07/22–24, 07–10, 10–16, 16–20 and 20–22. Stops lacking a headway statistic use a same-mode/day/band estimate, then 300 seconds. Missing rides use fixed km/h: metro 25, RER 45, train 50, tram 18, bus 15. Short walking connectors use 4.8 km/h. Inter-stop samples exclude separate stop dwell; frequency, holiday, direction/branch headways and platform access remain approximations. Missing departure uses weekday daytime explicitly. No live or historical departure availability is asserted.

The archive inspection for this pilot did not establish coverage for almost all 2022–23 survey dates; the earliest inspected 2023 snapshot lacked shapes. A matched mode and duration therefore describes a plausible synthetic realization, not recovery of the original trip.

## Post-route observations

The optional selected-route [movement and GNSS pilot](MOVEMENT_SIMULATION.md) creates dense observations after fitting, reusing the exact parameters and seed used to score its movement duration. Intermediate-stop anchors are attached before candidate scoring. Preview parameter edits do not refit endpoints or overwrite the fit. Timings are conditional synthetic estimates; matching a total duration does not validate signal locations or historical speeds. Automatic full-dataset observation generation remains outside this pilot.

## Bounds, measurements and reproduction

Batches default to 100 source records, capped at 1,000; imports cap at 1,000,000 rows. Completed results accumulate in session memory. Export uses existing disposable workers and 1,000-trip partitions; the final archive still accumulates in memory. Use smaller batches and export/delete completed batches on constrained machines. Persistent jobs, resumed full-dataset execution, population expansion, linked journeys and per-point timing are subsequent work.

```sh
npm run benchmark:netmob                  # import/exploration only
npm run benchmark:netmob -- 1,10,100       # explicitly calls local ORS only
```

Inputs must have the supplied filenames in `local/`. Results go to ignored `.benchmark-output/netmob/`. Each count starts a fresh Node process; the local ORS server remains warm. The fixture takes the first keys in ten mode strata (MAP, VPC, VELO, VAE, METRO, BUS, RER/TRAIN, TROTTINETTE, 2RM, AUTRE), round-robin. Counts are nested and use seed 90314, realization 0, 12 trials, 1.5 km walking / 5 km cycling access. All public services are absent from this benchmark.

Measured 2026-09-14, macOS arm64 / Apple M2 Max / Node 26.3.0:

| Records | Routing time | Completed / acceptable / poor / failed | ORS requests | Requests per completed route | Within-area | Peak process RSS |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 0.088 s | 1 / 1 / 0 / 0 | 12 | 12.0 | 1 | 1,257 MiB |
| 10 | 9.64 s | 9 / 5 / 4 / 1 | 236 | 26.2 | 4 | 3,105 MiB |
| 100 | 59.62 s | 97 / 79 / 18 / 3 | 3,065 | 31.6 | 28 | 3,117 MiB |

The 100-record run processed 1.68 source rows/s, produced 1.63 routes/s, and accepted 79% of selected rows (81.4% of completed routes). Median absolute error among completed routes was 68.3 s. All three failures lacked a sequence-compatible itinerary within access limits; five street-cache hits occurred. The sample excludes geographically ineligible rows and rows without usable departure/duration. Key ordering, equal mode strata and repeated participants make it nonrepresentative: it understates dominant walking/car shares, omits rarer modes, and is not an unbiased full-run fit-rate estimate. A naive extrapolation of this single sample to 75,784 eligible rows is ~12.6 hours / 2.3 million requests, not a forecast or authorization to run it.

Full-file Node import took ~1.14 s EMG / 0.46 s cube; filtered page queries took ~31 ms / 17 ms. Import-only peak RSS was 749 MiB. In-app browser imports were 0.85 s / 0.38 s (reader/index time, excluding file selection/hashing). Peak RSS above includes both imports, decoded network/timing assets and search heaps; it excludes the separate ORS Java process and is not a browser memory measurement. The browser skips transit asset loading for known street-only jobs. The 100-record result does not prove 1,000-record or full-dataset memory safety.

## Verification

The separate [local runner](NETMOB_RUNS.md) now provides explicit-folder checkpoints and incremental part exports while reusing this routing pipeline. The browser Local runs panel configures, starts, pauses, resumes and reviews these jobs; its pilot batches retain the bounds above. Local jobs use a separate process and disk folder rather than session batches. Full-dataset endurance and targeted retry workflows remain unvalidated.

The asset loader accepts both raw gzip and responses already decoded by HTTP Content-Encoding; asset URLs are resolved from the document base before crossing into the worker. This supports Vite and static hosting beneath a project path.

Synthetic Parquet fixtures cover schema recognition, sparse fields, destination joins, repeated geometry, duplicate keys and independent GeoParquet readback. Domain tests cover holes/multipart sampling, deterministic proposals, temporal anomalies, repeated/mixed mode sequences, wait/ride totals, poor-fit retention, inference, short connectors, snapping rejection, cancellation and service failure. GPX parsing verifies source metadata and elapsed leg timings without trackpoint times. `python3 scripts/test-transit-timing.py` verifies calendar exceptions, after-midnight service-day rollover, headway medians and bounded sample storage. Existing Manual state, pairing, transit and export regressions remain in `npm run check`.

Browser verification on 2026-09-14 used the supplied local files and local ORS: both imports, filtering, record inspection, within-area generation, a 100-row batch, cancellation retaining 7 results, retry of the remaining 93 after changing filters/seed, and preservation of Manual selections were exercised. Download readback verified 93 Parquet trips and 81 acceptable-only GPX files. A recorded metro → train example fitted 56.9 modeled minutes against 56 observed minutes; its seven legs / 191 vertices, timing sum, source identity and attribution survived both export formats. Map-to-list selection, 50-row record/route pagination, Enter activation and narrow layout were verified. The in-app browser did not emit its automation download event, so actual files in Downloads were used to verify completion. Browser-wide memory and full-dataset execution were not measured.
